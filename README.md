# FormCheck AI

> Choose a routine. Put your phone down. Just train.

FormCheck is a mobile-first browser workout coach built for Wanted AI Championship 2026.

## Problem

People training alone cannot easily see how their form changes during a set. A mirror requires looking away from the movement, and a recorded video provides feedback only after the workout. Routine apps can tell users what to do, but they do not observe how the movement is performed.

## Solution

FormCheck turns a phone camera into a real-time workout coach. For supported movements it tracks pose landmarks, counts complete repetitions, evaluates form that the camera can reliably measure, and guides set completion, rest, and the next step. The intended flow after Start is hands-free.

> Routine apps tell you what to do. FormCheck watches how you do it.

FormCheck provides exercise-form feedback only. It does not diagnose medical conditions, predict injury, or replace a qualified coach or clinician.

## Demo

[Current deployed demo](https://formcheck-ai-phi.vercel.app). This README update does not deploy a new build.

The competition route uses actual camera input and MediaPipe inference. It contains no synthetic pose, injected rep event, generated score, or prerecorded report.

```text
/routines/squat-two-set-test
```

`Squat Demo` runs five Squats × two sets with a five-second rest. General routines keep their normal rest settings. Use Hybrid + Minimal and keep Debug off for the presentation.

The intended 45–60 second excerpt is:

1. Open the labeled Squat Demo routine
2. Allow camera access and reach READY with one full body
3. Complete two normal reps and show real counts plus GOOD
4. Complete an accepted shallow rep and show CHECK FORM plus the depth cue
5. Correct the next rep and show GOOD
6. Complete Set 1 and show Rest → Next Set
7. Show only the report generated by the same measured session

See [demo checklist](docs/demo-checklist.md) for preflight, timing, and recovery procedures.

## Architecture / Workflow

1. `getUserMedia` starts the front camera by default; the preview and overlay are mirrored together
2. MediaPipe Pose Landmarker returns 33 normalized and world landmarks in browser `VIDEO` mode[^1]
3. Body Visibility Gate requires one confident full body before analysis can start
4. The registered exercise analyzer converts landmark history into phases, reps, and measurable form results
5. Workout Engine advances sets, absolute-deadline rest, timed exercises, and the next movement
6. Feedback Engine selects screen and Web Speech cues; the report stores only captured workout results

Camera, inference, analysis, feedback, and report construction run in the browser. See the canonical [Mermaid architecture source](docs/architecture.md).

## Pose Estimation

`Camera → MediaPipe Pose Landmarker → 33 Pose Landmarks → Body Visibility Gate → Exercise Analyzer → Workout State Machine / Form Evaluation → Feedback / Report`

> “We use AI where perception is needed and deterministic rules where consistent exercise decisions are needed.”

MediaPipe performs computer-vision pose estimation. After perception, FormCheck uses landmark processing, confidence gates, temporal smoothing, hysteresis, minimum state duration, debounce, deterministic exercise state machines, and explicit form rules. Low-confidence input becomes unable to evaluate, never bad form.

The pretrained Google MediaPipe Lite model and compatible WASM runtime are prepared locally under `public` using `npm run setup:pose`; their binaries are excluded from Git. FormCheck does not train its own pose model. Inference attempts a GPU delegate first and falls back to CPU. Default target inference rate is 20 FPS; QA mode can select 10, 20, or 30 FPS. Inference and canvas rendering use separate animation loops, and React updates are throttled.

## Exercise Logic

| Exercise | Current analysis | Validation status |
| --- | --- | --- |
| Squat | Complete phase-cycle rep count; depth; trunk lean; conditional frontal knee alignment | Extensive synthetic scenario/unit coverage; physical-phone calibration still required |
| Push-Up | Complete rep count; elbow-depth cue; side-view body alignment | Synthetic unit coverage; broader real-person calibration required |
| Lunge / Reverse Lunge | Complete rep count; unambiguous left/right side; depth; basic trunk alignment | Synthetic unit coverage; broader real-person calibration required |
| Plank | Workout Engine duration; side-view body alignment | Synthetic unit coverage; physical camera-angle validation required |
| Other catalog movements | No analyzer | Shows `ANALYZER NOT AVAILABLE`; user must Skip |

Squat counting requires `STANDING → DESCENDING → BOTTOM → ASCENDING → STANDING`. Incomplete cycles, bottom holds, small knee bends, implausibly fast jumps, and interrupted tracking do not count. Its explainable score uses Depth 40%, Trunk 35%, and Knee Alignment 25%; an unavailable category is removed from the denominator instead of receiving 0 or 100. See [Squat calibration](docs/squat-calibration.md).

## Feedback

- Hybrid: full visual feedback with essential voice cues
- Screen Only: all workout information remains visible and speech starts muted
- Voice Only: speech is primary while essential visual state remains available
- Minimal: start, milestone counts, important corrections, set/rest, and next exercise
- Normal: Minimal plus more intermediate counts
- Detailed: nearly every rep plus movement-phase guidance

The in-workout Mute control immediately calls `speechSynthesis.cancel()`. Identical messages inside 1.5 seconds are discarded, messages longer than 48 characters are rejected, and form cues have per-issue cooldowns. FormCheck does not control another app's music or the operating system's audio focus. Web Speech output, mixing, Bluetooth routing, and background behavior vary by browser and OS.[^2]

## State Handling / Routine System

The Explore surface contains ten built-in demo routines with category filters. It is not a live community: there are no accounts, public profiles, remote creators, rankings, publishing, or cross-user data.

Users can save a demo routine or create a local routine with title, description, difficulty, ordered exercises, sets, reps or duration, and rest. Up/down controls change exercise order. Saved/custom routines resolve through Routine Detail, Workout Setup, and Workout Engine on the same browser origin.

Routine, report, and Squat-detail persistence is isolated behind versioned `localStorage` adapters. A future backend is not included in this submission.

## Privacy

> Pose analysis runs on your device. Your camera feed is not uploaded.

The application has no frame-upload route, workout backend, analytics SDK, remote inference service, or microphone capture. Runtime model and WASM assets load from the current deployment origin; these requests do not carry camera frames or workout records. Camera pixels are processed and discarded.

Stored data is limited to saved/custom routines, up to 20 validated workout reports, and the latest detailed Squat evaluation. QA performance and landmark replay files download only after explicit tester actions; landmark coordinates may still be sensitive movement data and should be handled with consent.

## How to Run

Requirements: Node.js 20.9 or newer and npm.

```bash
npm ci
npm run setup:pose
npm run dev
```

Camera access requires the same device's `localhost` or a valid HTTPS origin. A phone opening a computer's plain LAN HTTP address is not a supported secure context.

For deployment, set `SITE_URL` to the canonical HTTPS origin and run `npm run setup:pose` before build so `public/models` and `public/mediapipe/wasm` are available. See the [production deployment checklist](docs/production-deployment.md).

## Validation

```bash
npm run setup:pose
npm run test
npm run lint
npm run build
```

Automated tests cover the workout state machine, analyzer state semantics, Squat calibration scenarios, form scoring, visibility and multi-person gates, pose-overlay mapping, storage validation, report calculations, voice queue rules, camera error messages, and production asset integrity.

These are primarily unit and synthetic landmark/metric tests. They do not verify camera permissions, MediaPipe runtime speed, real-person accuracy, heat, battery use, audio mixing, or long-session stability on a physical phone. Use the [mobile device QA checklist](docs/mobile-qa.md), [product audit](docs/product-audit.md), and [technical notes](docs/technical-notes.md) before submission.

## Limitations

- Physical release validation is incomplete: Safari rep-count and Hybrid voice issues were reported; physical-device retests remain pending. Unit/replay tests are not real-person accuracy evidence.
- Squat has the deepest automated coverage; other analyzers need broader real-person calibration
- A single RGB camera cannot reliably measure force, joint loading, pain, injury risk, or occluded body geometry
- Alignment feedback is omitted when confidence or camera angle is unsuitable
- Fast motion, blur, phone movement, poor light, occlusion, or leaving frame can pause or reject analysis
- Two-person handling pauses analysis but does not identify the intended user
- Front/rear switching depends on the device honoring `facingMode`
- Browser speech, background music mixing, screen lock, heat, and battery behavior remain device-controlled
- Data is local to one browser origin; there is no login, cloud synchronization, or cross-device history
- The local demo library is not a live community service
- Unsupported catalog exercises require manual Skip and receive no fabricated score
- A complete live 2 × 5 demo may exceed 60 seconds; edited footage must preserve truthful session continuity

Public release excludes competition submission documents, personal camera/landmark logs, and downloaded third-party model/WASM binaries. [Public QA limitations](docs/release-qa.md) and [third-party asset notes](NOTICE.md) describe the boundaries.
